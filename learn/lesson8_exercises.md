# 第8课 实操手册：GRPO 强化学习（命令行版）

> 运行演示：`python learn/lesson8_grpo.py`
> 核心认知：RL 数据里**没有答案**。模型自己写 6 份答案 → 裁判打分 → 组内比出优势 → 好答案整体加强、坏答案整体抑制。

---

## 与前面所有阶段的本质区别（背下来）

| 阶段 | 数据里有什么 | 模型训练时自己生成内容吗 |
|---|---|---|
| 预训练/SFT | 文本+每字标签 | 否 |
| DPO | 好答案+坏答案 | 否 |
| **GRPO** | **只有问题，answer=""** | **是！采样6份答案** |

没有逐字纠错，只有"这整个答案值得加强/抑制"的赏罚。这就是 RL 与监督学习的分水岭——也是模型能**超越示范数据**（R1 式长推理）的唯一途径。

## 一个 GRPO 步骤的五拍（对照 train_grpo.py）

1. **采样**（:80-86）：每个问题生成 6 份答案，temperature=0.8 制造多样性（探索）
2. **打分**（:37-68）：规则分（长度/思考段/重复度）+ 奖励模型分（本机 `internlm2-1_8b-reward`）
3. **组内比较**（:121-124）：`优势 = (得分 - 组均分) / 组标准差` —— 全班平均 30 分的卷子，35 分就是好学生
4. **赏罚**（:135-143）：`loss = -优势 × logP(答案每个token) + KL缰绳`——好答案每个字的赌注推高，坏答案压低
5. **缰绳**（:132-133 + 冻结的 ref 模型）：与参考模型的 KL 惩罚，防止为刷分跑偏成胡言乱语

## 实验一：灵魂演示（3 分钟）

```bash
cd /app/zdf/minimind && python learn/lesson8_grpo.py
```

看点：Part 1 的 6 份真实采样答案和得分（简化版只用规则分，真实训练还叠加奖励模型）；Part 2 优势从 -1.75 到 +1.71 的分化。
诚实说明：得分普遍难看（-1.0、-0.25）是正常的——64M 弱模型答得差，RL 从负分起步。

## 实验二：亲手跑真 GRPO（约 5-7 分钟）

```bash
cd /app/zdf/minimind/trainer
python train_grpo.py --epochs 1 --batch_size 2 --num_generations 4 \
  --max_gen_len 150 --data_path ../dataset/rlaif_smoke.jsonl \
  --from_weight full_sft --save_weight grpo_8 \
  --log_interval 1 --num_workers 0 --debug_mode --debug_interval 3
```

**已验证**：16 条数据 8 步，每步要完成"采样 2×4 份答案 + 策略/参考/奖励三个模型前向"，比监督训练慢一个量级。参考输出：`Reward: -2.03 → -1.94`，`KL_ref ≈ 0`。
`--debug_mode` 会打印真实的问题、6 份答案全文和每份的得分（含奖励模型分）——**这 20 行日志比任何讲义都直观**。

日志字段对照：
- `Reward`：本步所有答案的平均分（越高越好）
- `KL_ref`：偏离参考模型的程度（缰绳松紧）
- `Adv Std/Mean`：优势的分布（_std≈1 是组内比较标准化的结果）
- `Avg Response Len`：答案平均长度（观察 reward hacking 的窗口！）

## 验收自测

1. RLAIFDataset 和 SFTDataset 返回的东西差在哪？这个差异意味着什么？
2. 优势(advantage)怎么算的？为什么必须减组均分？
3. "加强一个答案"在参数层面具体是什么操作？
4. KL 缰绳和参考模型防的是什么？
5. 一句话说出 GRPO 和 DPO 的共同点与区别。

<details>
<summary>自测答案（先自己答，再展开）</summary>

1. SFT 返回 input_ids+labels（每字答案）；RLAIF 只返回 prompt，answer 是空串。意味着训练信号不再来自数据，而来自"生成→打分"的闭环。
2. (得分-组均分)/组标准差。不减均分，简单题目全体高分会被误判为"全好"；组内相对化消除了题目难度差异。
3. 把该答案序列中每个 token 的 logP 乘上正优势加进损失——梯度上升推高这些 token 的赌注；负优势反之压低。
4. 防止模型为迎合裁判而偏离语言能力（比如输出乱码恰好骗过规则）——一切改动都要以"不远离出发点"为代价。
5. 共同点：都以"相对好坏"为信号、都有参考模型/KL 约束、都属于对齐。区别：DPO 用人工标注的偏好对（离线、不生成）；GRPO 用自己生成+裁判打分（在线、能超越数据，但不稳、贵、易被钻空子）。
